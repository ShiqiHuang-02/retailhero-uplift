## 本轮交付

1. `sql/01_transaction_features.sql`：从原 notebook 提取交易审计、交易去重聚合与七项行为特征。执行器先检查交易金额、时间、门店版本和金额缺失，审计不通过则停止，避免用 MAX 掩盖冲突。
2. `sql/02_policy_marts.sql`：使用窗口函数进行确定性排序，生成客户策略长表、汇总效果、选中客户画像及策略集合重合度。
3. `scripts/build_portfolio.py`：读取原模型、固定划分，计算配对 Bootstrap、验证集触达曲线、效果校准、成本情景、样本量规划，并核对原结果。
4. `04_portfolio_analysis.ipynb`：阅读新增分析结果的入口。
5. `reports/portfolio/项目展示报告.html`：可离线打开、含嵌入图片的展示报告。
6. `tableau/RetailHero_营销决策_草稿.twbx`：三页看板、七张工作表和两个成本参数的 Tableau 工作簿草稿。包含汇总数据，不包含客户明细。
7. `docs/online_experiment_plan.md`：拟议线上实验设计；没有实际开展实验。

## 复现

在项目根目录运行：

```bash
.venv/bin/python -B scripts/build_portfolio.py --audit-raw
```

默认 3,000 次 Bootstrap，随机种子 20261109。仅更新新增的 `reports/portfolio/` 和 `tableau/` 数据、报告与工作簿，不更新原模型和旧结果表。

省略 `--audit-raw` 可复用现有处理后数据，验证报告会明确记录没有重新核查原始交易特征。原始交易压缩文件约 581 MB，完整审计会多次扫描。路径、模型和标签需可信；joblib 模型只加载此项目已有本地文件。

若原始数据或模型不存在，先按原项目说明完成 01 → 02 → 03。新增脚本不会静默建立新划分，也不会从网上自动下载数据。

## 不确定性分析口径

- 主要比较仍是 20% 触达比例下的 Uplift − Response。
- 固定模型、分数、选人结果和处理概率，客户层面的差值为 `(π_uplift − π_response) × DR_score`。
- 对同一个差值向量进行 IID 客户重采样，每次抽取原样本量，计算均值并乘 1,000；使用百分位 2.5%／97.5% 区间。
- 不在每次重采样中重训、重新估计分数、重排客户或重新选预算；不包含训练、排序阈值估计和方案选择的不确定性。
- 没有校正多重比较，没有覆盖率保证，也没有恢复全新测试证据。Bootstrap 结果与正态近似接近，只能说明此重采样设置下方法较一致。
- 随机基线使用相同名额的期望选择概率，不额外混入一次随机选人噪声。
- 全样本购买率差异、测试集策略收益、验证集探索曲线属于不同估计对象，不互相替代。

## 业务口径

所有策略增量以每千名候选客户为分母，20% 对应约 200 次触达。画像只描述被选中的客户，不把画像差异解释为因果效应。

净收益情景假设：每名增量购买客户产生固定的贡献毛利，触达成本按每次触达计算；同一货币单位。没有真实成本、处理后订单金额或贡献毛利，因此不能宣称已实现 ROI。历史消费金额不能替代处理后的增量收入。

净收益区间固定成本和毛利，只线性变换效果区间。曲线区间为逐点区间，不能据此给选出的最高点提供有效的选后保证。若未来要选预算，应先在验证数据确定方案，再通过新的独立样本或线上实验验证。

常数处理概率情景仅改变 e 的假定数值，不是对条件混杂的完整敏感性分析，也不是倾向得分模型或随机化证明。
